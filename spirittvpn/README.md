# SpirittVPN — Telegram-бот и Mini App

<p align="center"><img src="app/assets/spirittvpn_logo.png" width="200" alt="SpirittVPN"></p>

VPN-сервис внутри Telegram. Бот служит входной точкой, а основной интерфейс — встроенное **Telegram Mini App** (React + TypeScript + Vite). В нём главная, подписка и тарифы, устройства, рефералы, профиль и отдельная админ-панель с ролями. Бэкенд построен на Python 3.12, aiogram 3, aiohttp, SQLAlchemy 2, Alembic и PostgreSQL.

> **Принцип честности.** Бот и приложение никогда не показывают фиктивный рабочий доступ. При `VPN_PROVIDER=none` пробный период, покупки и устройства закрыты статусом «VPN-серверы готовятся к запуску». Режим `mock` подписывает каждую ссылку «ТЕСТ — не рабочий VPN» и запрещён в production.

### База данных (новое в 0002)

| Таблица | Назначение |
|---|---|
| `devices` | устройство = отдельный клиент панели (`external_username` уникален, `external_id`), статус, привязка к подписке |
| `bonus_ledger` | журнал бонусных дней (реферальные, промо, админ, корректировки). `UNIQUE(unique_key)` гарантирует один бонус каждого типа на приглашённого |
| `staff` | роли сотрудников (поддержка, тех. специалист, администратор) |
| `vpn_nodes`, `vpn_errors` | статус нод с последней проверкой и журнал ошибок API панели |
| `users.referrer_id` | пригласивший; задаётся только при первой регистрации |
| `subscriptions.device_limit`, `is_lifetime` | лимит устройств и бессрочность |
| `plans` / `orders`: `device_limit`, `is_lifetime` | тариф и снимок условий в заказе. Изменение тарифа не меняет оплаченные заказы |
| `promo_codes.allowed_plans` | тарифы, к которым применима скидка |

Миграция 0002 сохраняет данные: прежние `vpn_accounts` становятся устройствами «Основное устройство», удаляются только старое приветствие и никогда не настраивавшиеся старые тарифы без заказов. Upgrade и downgrade проверены на SQLite и PostgreSQL 16.

## 3. Запуск

### Через Docker (сервер)

```bash
git clone <repo> && cd <repo>/spirittvpn
cp .env.example .env && nano .env        # BOT_TOKEN, OWNER_IDS, POSTGRES_PASSWORD, PUBLIC_BASE_URL, ...
docker compose up -d --build             # сборка Mini App, миграции, бот, PostgreSQL, Redis, бэкапы
docker compose logs -f bot
```

Mini App нужен **публичный HTTPS**. Поставьте перед портом 8080 (открыт только на `127.0.0.1`) reverse-proxy с TLS, например Caddy:

```
vpn.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

После этого задайте `PUBLIC_BASE_URL=https://vpn.example.com`. Бот сам поставит кнопку меню и web_app-кнопку на `https://vpn.example.com/app/`. В BotFather можно дополнительно задать `/newapp` или `/setmenubutton`, но это не обязательно.

### Без Docker (разработка)

```bash
python3.12 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
cd webapp && npm ci && npm run build && cd ..
cp .env.example .env     # DATABASE_URL=sqlite+aiosqlite:///./data/spirittvpn.db, VPN_PROVIDER=mock
mkdir -p data && alembic upgrade head && python -m app
```

Фронтенд в режиме разработки: `cd webapp && npm run dev` (прокси `/api` на :8080). Вне Telegram приложение показывает экран «Открой из бота»: без подписанного `initData` API не отвечает.

### BotFather

1. `/newbot` → токен в `BOT_TOKEN` (никому не показывайте, при утечке — `/revoke`).
2. `/setuserpic` → `app/assets/spirittvpn_logo.png`.
3. Для оплаты в рублях: **Payments** → провайдер → токен в `PAYMENT_PROVIDER_TOKEN`.
4. Свой ID (@userinfobot) → `OWNER_IDS`.

## 4. Тарифы, промокоды, рефералы

Каталог по умолчанию создаётся при первом запуске из `.env`:

| Код | Тариф | Срок | Устройств | Цена |
|---|---|---|---|---|
| `solo30` | Solo | 30 дней | 1 | 100 ₽ |
| `duo30` | Duo | 30 дней | 2 | 200 ₽ |
| `q3` | 3 месяца | 90 дней | `PLAN_Q3_DEVICES` (2) | 250 ₽ |
| `y1` | 1 год | 365 дней | `PLAN_Y1_DEVICES` (3) | 1 150 ₽ |
| `life` | Lifetime | без регулярных продлений | `PLAN_LIFE_DEVICES` (3) | 5 000 ₽ |

Дальше цены, сроки, лимиты, описания и доступность меняются в **админ-панели → Тарифы** (или `/plan_set` в боте). Фронтенд берёт тарифы только из API. При продлении активной подписки срок добавляется к текущему, а лимит устройств не уменьшается. Lifetime означает отсутствие регулярных продлений на всё время работы сервиса по условиям оферты; вечная доступность инфраструктуры не обещается.

Промокоды: `days` (дни), `percent` и `fixed` (скидка). Доступные настройки: лимит активаций, срок, группа пользователей, «только новым», список тарифов для скидки. История использования ведётся в БД.

Рефералы: +3 дня пригласившему после активации пробного периода другом и +7 дней после его первой подтверждённой оплаты. Размеры и включение программы меняются в админ-панели. Защита: один реферер на пользователя (задаётся только при первой регистрации), самоприглашение игнорируется, бонус каждого типа начисляется один раз (`UNIQUE`), повторный webhook ничего не начисляет. **Ограничение:** проверка по Telegram ID не выявляет все мультиаккаунты.

Внутреннего баланса в проекте нет, поэтому пополнение и списание не реализованы.

## 5. Роли

| Роль | Откуда | Права |
|---|---|---|
| Владелец | `OWNER_IDS` | всё, включая персонал, возвраты и управление нодами |
| Администратор | `ADMIN_IDS` или панель | всё, кроме персонала, возвратов и управления инфраструктурой |
| Поддержка | панель | обращения, просмотр пользователей |
| Технический специалист | панель | статистика, серверы (проверка), устройства, просмотр пользователей |

Права проверяются на сервере дважды: в обработчике API и в сервисном слое. Каждое привилегированное действие пишется в `audit_log`. Секреты платёжки и панели в интерфейс не попадают.

## 6. Подключение Remnawave (+ h1cloud)

Клиент написан по официальному контракту `remnawave/backend` (libs/contract **v3.4.15**): `POST /api/users`, `GET /api/users/{id}`, `GET /api/users/by-username/{u}`, `PATCH /api/users`, `DELETE /api/users/{id}`, `GET /api/nodes`, авторизация `Bearer`. **Перед запуском сверьте API со страницей `/backend-tools/scalar` своей версии панели.** С живой панелью интеграция не проверялась, только с локальной имитацией контракта в тестах.

1. Арендуйте VPS (например, у h1cloud), установите Remnawave Panel и Node по официальной документации (docs.rw), создайте ноду, хосты и Internal Squad.
2. В панели: **API Tokens** → создайте токен.
3. В `.env` укажите `VPN_PROVIDER=remnawave`, `REMNAWAVE_URL=https://panel.example.com`, `REMNAWAVE_TOKEN=…`, `REMNAWAVE_SQUADS=<uuid сквада>`. Если бот ходит в панель по внутренней сети по HTTP, добавьте `REMNAWAVE_LOCAL=true`.
4. Перезапустите бота. Ноды появятся в админ-панели после первой проверки (каждые `NODE_CHECK_INTERVAL_SECONDS`).

Как устроено: каждое устройство — отдельный пользователь панели `sp_<tgid>_<hex>` со сроком подписки и `hwidDeviceLimit` (по умолчанию 1). Пользователь получает свою `subscriptionUrl`. Отзыв удаляет клиента в панели; строка в БД помечается отозванной только после подтверждения. Повторяются только идемпотентные запросы (GET, PATCH, DELETE). Создание не повторяется вслепую: после потерянного ответа бот ищет клиента по уникальному имени. Ошибки панели пишутся в `vpn_errors` и показываются в админке; несинхронизированные изменения дотягивает фоновая задача. **Ограничение:** число физических устройств строго контролируется только при включённом HWID в панели и клиентах, которые передают HWID. Копирование ссылки иначе не предотвратить.

Marzban тоже поддерживается (`VPN_PROVIDER=marzban`) без мониторинга нод.

## 7. Подключение оплаты

- **Telegram Payments** (`PAYMENT_PROVIDER=telegram`): `RUB` + `PAYMENT_PROVIDER_TOKEN` или `XTR` (Stars, цены в звёздах). В Mini App используется `createInvoiceLink` → `openInvoice`. Подписка включается только по `successful_payment`, а `pre_checkout_query` проверяет заказ, сумму и срок. Возврат Stars выполняется из админ-панели через `refundStarPayment`; для фиата сначала верните деньги у провайдера, затем отметьте возврат в админке. Чеки 54-ФЗ передаются через `provider_data` вашего провайдера и пока не настроены.
- **Внешний провайдер с webhook**: реализуйте `PaymentProvider.create_payment` и `parse_webhook` (проверка подписи), webhook — `POST /payments/<name>/webhook`.
- **Тестовый режим** (`PAYMENT_PROVIDER=test`, только разработка): события подписаны HMAC и помечены как TEST, в выручку не входят.

## 9. Безопасность

- `initData` проверяется на сервере официальным алгоритмом (HMAC-SHA256 с ключом `WebAppData`, помощник aiogram) плюс свежесть `auth_date`. Telegram ID, роль и цена из параметров клиента не принимаются.
- Rate limit API (`API_RATE_PER_MINUTE`), отдельные лимиты на промокоды и тикеты. Лимит тела запроса, `Cache-Control: no-store` для API, `nosniff`.
- Ссылки подключения не логируются и не хранятся в БД, в боте отправляются с `protect_content`. Чужие устройства, заказы и тикеты недоступны (404).
- Остальное, как и раньше: секреты только в `.env`, фильтр токенов в логах, бэкапы `pg_dump`, production запрещает mock/test-режимы.

## 11. Что требует внешних ресурсов

| Функция | Статус |
|---|---|
| Бот, Mini App, кабинет, устройства, рефералы, промокоды, админка, роли, аудит, тесты | реализовано и проверено |
| Реальный VPN-доступ | нужен сервер с Remnawave (или Marzban) и токен; адаптер написан по контракту, но с живой панелью не проверялся |
