# Админ-панель, поддержка и ручная выдача подписок

## Главный администратор

Права определяются **только по числовому Telegram ID**. Username для авторизации не используется: его можно сменить или занять.

| Источник | Роль | Как меняется |
|---|---|---|
| `OWNER_TELEGRAM_ID` в `.env` | владелец | только в `.env` сервера + перезапуск |
| `ADMIN_IDS` в `.env` | администратор | только в `.env` |
| таблица `admin_roles` | администратор | владелец в панели («Администраторы») или в боте (`/admin` → «👑 Администраторы») |
| `/setup <код>` | владелец | однократно, если владелец ещё не назначен |

Для `@cupsov` установлено `OWNER_TELEGRAM_ID=8901325133`. Связка ID ↔ username подтверждена Telegram Bot API (`getChat(8901325133)` → `username: cupsov`). Её же прислал Telegram в апдейте, когда пользователь нажал `/start`.

**Если ID владельца неизвестен.** Оставьте `OWNER_TELEGRAM_ID` пустым и запустите бота. В **логе сервера** появится строка `/setup <код>`. Тот, у кого есть доступ к серверу, отправляет эту команду боту со своего аккаунта и становится владельцем. Код работает один раз и только пока владельца нет. Свой ID любой пользователь узнаёт командой `/whoami`.

**Защита от эскалации:**
- назначать и снимать администраторов может только владелец (проверяется на сервере);
- обычный админ не может снять владельца;
- никто не может снять самого себя;
- админов из `.env` нельзя снять из панели;
- роль проверяется в БД **при каждом запросе**, поэтому снятые права перестают действовать сразу, даже при живом токене;
- заблокировать администратора нельзя: сначала нужно снять права.

## Где админ-панель

- **Внутри Telegram:** Mini App → «Кабинет» → «🛠 Админ-панель». Панель открывается в том же окне Telegram, возврат кнопкой «← В приложение» или системной «Назад». Короткоживущий токен админа выдаётся backend только после проверки `initData` и роли.
- **В браузере:** `https://ДОМЕН/admin` → Telegram ID → одноразовый код от бота.
- **В чате с ботом:** `/admin`. Там поиск, выдача подписок, блокировка, тарифы, рефералы, настройки, ноды, ошибки, журнал, администраторы и обращения. Плюс `/ticket SUP-12345`.

## SpirittVPN ID

Каждому пользователю при первом входе выдаётся постоянный ID вида `SV-8K4M2Q`:

- 6 случайных символов без похожих `0/O/1/I/L`, около 10⁹ вариантов; ID не последовательный и не раскрывает число пользователей;
- уникальность гарантирует ограничение БД; при повторных входах ID не меняется;
- пользователь видит ID в «Кабинете» (с кнопкой копирования) и по команде `/whoami`;
- по ID ищет **только администратор**; пользовательских эндпоинтов поиска нет;
- поиск принимает Telegram ID, `@username` (или часть имени), `SV-XXXXXX`, `sv-xxxxxx` или просто `XXXXXX`.

## Ручная выдача подписки

Панель: «Пользователи» → пользователь → «🎁 Выдать / изменить подписку». Бот: `/admin` → «👤 Найти пользователя» → «🎁 Подписка: выдать / изменить».

| Операция | Что происходит |
|---|---|
| **Продлить** | срок добавляется к текущей дате окончания, если подписка активна; если истекла — отсчёт от текущего момента. Оставшееся время не теряется |
| **Новая подписка** | срок заменяется: от сейчас (или от указанной даты начала в прошлом) до «сейчас + срок» или до указанной даты окончания |
| **Точная дата окончания** | задаётся конкретная дата (должна быть в будущем) |
| **Бессрочно** | `is_lifetime = true`, `expires_at = NULL`. Это не «2099 год» |
| **Сократить** | дата окончания уменьшается; если она оказалась в прошлом, подписка истекает и ключи блокируются |
| **Завершить досрочно** | подписка истекает сейчас, ключи **блокируются** на нодах (ban); при повторном продлении они разблокируются |
| **Отозвать доступ** | подписка получает статус `revoked`, ключи **удаляются** на нодах; повторная выдача создаст новую подписку и новый ключ |

Параметры:
- срок в часах, днях, неделях или месяцах (в боте `12h`, `3d`, `2w`, `1m`), либо тариф;
- лимит устройств;
- **причина** — обязательна, видна только администраторам и попадает в аудит;
- **комментарий для пользователя** («Компенсация», «Подарок от администрации») — пользователь видит его в уведомлении и в истории подписки;
- уведомлять ли пользователя.

**Время.** Календарные расчёты (месяцы с учётом их длины: 31 января + 1 месяц = 28/29 февраля) выполняются в `DISPLAY_TIMEZONE` (по умолчанию `Europe/Moscow`). Даты без часового пояса читаются в этом поясе. В БД всё хранится в UTC.

**Согласованность с VPN:**
1. Сначала транзакция в БД (подписка, история, аудит).
2. Затем вызовы ноды: продление срока, создание первого ключа, если ключей нет, бан/разбан, удаление.
3. Ответ показывает, сколько операций нода подтвердила, сколько ошибок и сколько в очереди.
4. Неподтверждённые операции попадают в `vpn_operations` и повторяются воркером без дублей: имя клиента фиксировано, срок задаётся абсолютной датой.

В кабинете пользователя право на доступ (подписка) и фактический доступ (`access_state`) показаны раздельно. Пока нода не подтвердила операцию, пользователь видит «⏳ Ожидаем подтверждения VPN-сервера», а не «доступ выдан».

**Аудит.** Каждая операция пишет `audit_logs`: кто, когда, кому, что было и что стало, причина. История подписки хранится в `subscription_events`.

## Блокировка

«Заблокировать» требует причину:
- `users.is_banned = true`;
- подписка приостанавливается, ключи банятся на нодах;
- пользователь видит баннер; покупка, пробный период и устройства недоступны (HTTP 403 и сообщение в боте);
- **поддержка остаётся доступной**.

«Разблокировать» восстанавливает подписку, если её приостановила именно блокировка.

## Поддержка

**Пользователь** (Mini App → «Поддержка» или бот → «❓ Поддержка» / `/support`):
- создаёт обращение: категория (оплата, подключение, подписка, устройства, ошибка приложения, другое) и описание;
- в боте может приложить фото или файл;
- видит статус и историю, отвечает, закрывает обращение.

Номер обращения `SUP-XXXXX` случайный и уникальный. Ограничения:
- не больше `support_max_open_tickets` открытых обращений (по умолчанию 3);
- не больше 10 обращений в сутки;
- не больше 60 сообщений в час.

**Статусы:** Новое → В работе → Ожидает ответа пользователя → Решено → Закрыто. Ответ пользователя возвращает обращение в работу.

**Администратор** (панель «Поддержка», бот `/admin` → «🎫 Обращения», `/ticket SUP-…`):
- фильтры по статусу, категории и ответственному;
- ответ пользователю (бот отправляет его **владельцу обращения**, адресат берётся из `support_tickets.user_id`);
- внутренние заметки 🔒 (пользователь их не видит; БД запрещает пользователю создавать internal-сообщения);
- смена статуса, назначение и передача ответственного с уведомлением;
- просмотр вложений в боте.

Уведомления о новых обращениях получают все администраторы, а если ответственный назначен — только он.

**Изоляция.** Пользовательские маршруты (`/api/support/...`) ищут обращение по ID **и** владельцу. На чужое обращение возвращается та же ошибка «не найдено», что и на несуществующее, поэтому перебор ID ничего не даёт.

Вложения из Mini App не загружаются: файлы и скриншоты отправляются через бота, и это сказано в интерфейсе.

## Настройки поддержки

Панель → «Настройки»:
- `support_enabled` — приём обращений;
- `support_max_open_tickets` — лимит открытых обращений;
- ссылка на оператора задаётся в `SUPPORT_URL` в `.env`.

## API (сводка)

**Пользователь** (Bearer-токен после `POST /api/auth/telegram`):
- `GET /api/me` (с `public_id`, `account_status`, `access_state`, `remaining_seconds`)
- `GET /api/subscription/history`
- `GET|POST /api/support/tickets`
- `GET /api/support/tickets/{id}`
- `POST /api/support/tickets/{id}/messages`
- `POST /api/support/tickets/{id}/close`

**Администратор** (токен роли admin, роль проверяется в БД на каждом запросе):
- `GET /api/admin/me`
- `GET /api/admin/users?q=`
- `GET /api/admin/users/{tg_id}`
- `POST /api/admin/users/{tg_id}/grant`
- `POST /api/admin/users/{tg_id}/block|unblock`
- `GET|POST /api/admin/admins` (только владелец)
- `POST /api/admin/admins/{tg_id}/revoke` (только владелец)
- `GET /api/admin/support/tickets`
- `GET /api/admin/support/tickets/{id}`
- `POST /api/admin/support/tickets/{id}/reply|status|assign`


## Промокоды

Панель «🎟 Промокоды» или бот `/admin` → «🎟 Промокоды». Пользователь вводит код в боте («🎁 Промокод», `/promo`) или в Mini App (вкладка «Бонусы», «Есть промокод?» в «Тарифах»).

| Тип | Значение | Действие |
|---|---|---|
| `percent` | 1–90 % | скидка на **следующий заказ** |
| `fixed` | сумма в ₽ | скидка на следующий заказ; итог не меньше 1 ₽ (минимум ЮKassa) |
| `days` | 1–365 дней | сразу добавляет дни к подписке, либо создаёт подписку на 1 устройство и выдаёт ключ |

**Настройки промокода:**
- код (или автогенерация);
- лимит активаций;
- срок действия;
- включён или отключён;
- заметка.

Причина создания и отключения обязательна, всё пишется в аудит.

**Защита (на сервере):**
- строка промокода блокируется на время активации, поэтому лимит не превышается даже при одновременных запросах; дополнительно это гарантирует `CHECK activations <= max_activations`;
- `UNIQUE(promo_id, user_id)` — один пользователь использует код один раз;
- у пользователя может быть только одна неиспользованная скидка;
- скидка считается backend при создании заказа и фиксируется в заказе (`discount_minor`);
- после подтверждённой оплаты активация помечается `used`;
- отключение промокода или истечение срока аннулирует ещё не использованную скидку;
- частота ввода кодов ограничена (5 в минуту в Mini App, плюс блокировка повторного нажатия в боте).

Сообщения пользователю: «не найден», «срок действия истёк», «отключён», «лимит исчерпан», «вы уже использовали этот промокод».

В боте промокод создаётся одной строкой: `КОД ТИП ЗНАЧЕНИЕ [ЛИМИТ] [ДНЕЙ_ДЕЙСТВИЯ]`, например `SUMMER percent 20 100 30`.

## Обязательные документы и подписка на канал

**Документы.** При первом `/start` бот показывает логотип, приветствие и экран документов. До нажатия «✅ Принимаю условия» доступ закрыт ко всему.

Факт согласия пишется в `users.terms_version` / `terms_accepted_at` и в журнал `terms_consents`: Telegram ID, версия, ссылки на документы, время, источник (bot или miniapp).

Если документы изменились, увеличьте `TERMS_VERSION` в `.env`, и все пользователи примут их заново. Сохранённое согласие — это технический журнал. Его достаточность с юридической точки зрения проект не гарантирует.

**Канал.** Затем проверяется подписка на `REQUIRED_CHANNEL` через `getChatMember`:
- `creator`, `administrator`, `member` — подписан;
- `restricted` — подписан, только если `is_member = true`;
- `left`, `kicked` — не подписан.

При ошибке Telegram доступ **не** выдаётся, пользователь видит сообщение и кнопку повторной проверки.

Проверка выполняется на каждом действии в боте (middleware) и на каждом защищённом запросе Mini App: покупка, пробный период, устройства, ссылки, промокоды, бонусы. Положительный ответ кешируется на `CHANNEL_CACHE_SECONDS` (по умолчанию 300 с), отрицательный не кешируется. Обойти проверку прямыми callback-кнопками или командами нельзя: они проходят через тот же middleware.

Администраторы бота освобождены **только** от проверки канала, чтобы не потерять доступ к панели при ошибке настройки. Документы принимают все.
